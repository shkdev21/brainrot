# Steal a Brainrot — 웹 3D 클론 게임 개발 계획

작성일: 2026-08-25
출처 조사: 나무위키 "Steal a Brainrot" 문서 (메인 + 브레인롯/일반 + 도구 + 환생 + 특성 + 변이 하위 문서 전수 조사)

## 1. 원작 게임 요약 (조사 결과)

원작은 Roblox의 8인 시뮬레이션/타이쿤 게임(2025.5 출시, SpyderSammy 제작)이다. 핵심 루프:

1. **구매**: 중앙 레드카펫(스폰 존)에 브레인롯이 스폰되면 돈으로 구매 → 브레인롯이 자동으로 내 기지로 이동
2. **수입**: 기지에 있는 브레인롯이 초당 돈(income/s)을 생산. 총 수입 = Σ(브레인롯 기본 수입 × 변이 배율 × 특성 배율)
3. **훔치기**: 다른 플레이어의 기지에 침입해 브레인롯를 들고 내 기지까지 운반하면 소유권 이전. 단, **들면 이동속도 감소 + 도구 사용 불가**
4. **방어**: 기지 잠금(침입 차단, 쿨타임 존재) + 도구(함정, 메두사의 머리, 터렛 등)
5. **환생**: 재산과 브레인롯을 초기화하고, 필요 재료(특정 브레인롯)+돈을 대가로 환생 포인트 획득 → 도구 해금, 기지 층 확장(2환생 2층, 10환생 3층), 슬롯 증가

### 1.6 훔치기/방어 규칙 (원작 메커니즘)

- 브레인롯을 들면: 이동속도 감소, 도구 사용 불가 → 도주 게임이 됨
- 기지 잠금 상태에서는 침입 불가 (잠금은 쿨타임 후 재사용)
- 훔친 브레인롯을 **내 기지 영역에 가져가야** 소유권 이전
- 기지 주인이 서버를 나가면 그 브레인롯은 무주공해가 되고, 다른 사람이 때리면 소멸
- 좋은 브레인롯은 상위 층(2~3층)에 배치하는 것이 방어에 유리
- 친구는 잠긴 기지에도 입장 가능

## 2. 프로젝트 목표와 스코프

**목표**: 브라우저에서 바로 실행되는 3D "브레인롯 훔치기" 게임. 원작의 핵심 경험(구매→수입→훔치기→방어→환생 성장 나선)을 재현한다.

**핵심 결정 (기본값, 추후 변경 가능)**:

| 항목 | 결정 | 이유 |
|---|---|---|
| 멀티플레이 | **Phase 1: 싱글 + AI 봇 7명** → 아키텍처는 멀티 확장 대비 | 원작 8인 구도를 봇으로 재현. 서버 없이 배포 가능하며 난이도 관리 가능. 게임 로직을 순수 모듈로 분리해 나중에 WebSocket 서버 붙일 수 있게 설계 |
| 3D 엔진 | **Three.js + TypeScript + Vite** | 웹 3D 사실상 표준. 로우폴리 스타일에 적합, 생태계 성숙 |
| 캐릭터 | **오리지널 절차적 로우폴리 캐릭터** (밈 스타일: 동물×음식×사물 하이브리드) | Italian Brainrot 캐릭터의 저작권 리스크 회피. 스탯/등급 체계는 원작 데이터를 그대로 차용해 경제 밸런스 유지 |
| 데이터 | 원작 77종 스탯을 데이터 파일로 | `docs/research/brainrots_normal.json`을 게임 데이터로 변환 |
| 저장 | localStorage (자동 저장) | 싱글 기준 충분. 멀티 확장 시 서버 DB로 교체 |
| 플랫폼 | PC 브라우저 우선 (WASD+마우스) | 3D 조작 정확성. 모바일은 후순위 |

### 2.1 스코프 (Phase 1 포함 / 제외)

**포함 (MVP + 알파)**:
- 3D 맵: 중앙 레드카펫 스폰 존 + 8개 플레이어 기지 링 배치
- 1인칭/3인칭 캐릭터 조작 (WASD, 점프, 달리기)
- 브레인롯 스폰·구매·기지 이동·초당 수입
- 훔치기 풀 사이클 (들기→이속 감소→운반→소유권 이전)
- 기지 잠금 (쿨타임), 층 구조(1~3층)
- AI 봇 7명: 각자 기지 소유, 경제 활동(구매/수입), 공격/방어 행동
- 변이 3종(골드/다이아/무지개) + 한정 변이 이벤트
- 환생 5단계 (스타터) → 19단계 확장
- 도구 12종 (방망이, 함정, 점프 부츠, 투명 망토, 디스코볼, 메두사, 웹 슬링거, 터렛, 대쉬 검, 레이저 건, 순간이동, 방어막)
- 상점 UI (도구 구매), 브레인롯 정보 UI (등급/수입/변이)
- 옥션(경매) 이벤트: 고등급 브레인롯 입찰
- 사운드 (구매/훔침/기절/수입 틱 효과음)

**제외 (Phase 2+ 후보)**:
- 실시간 멀티플레이 (WebSocket)
- 퓨즈머신(합성), 거래 시스템, 듀얼 PVP, 트레이딩 플라자
- 특성 40종 전체 (Phase 1은 변이로 배율 다양성 확보)
- 시크릿/OG 등급 전체 (데이터는 준비하되 등장은 이벤트성)
- 모바일 터치 컨트롤

## 3. 아키텍처

```
src/
  core/               # 순수 게임 로직 (렌더링 무의존 — 향후 서버 재사용 가능)
    GameState.ts      # 전체 상태 스냅샷 (플레이어, 기지, 브레인롯, 경제)
    Economy.ts        # 수입 계산, 가격, 스폰 스케줄러
    Brainrot.ts       # 브레인롯 엔티티 (등급, 변이, 수입 배율)
    Carry.ts          # 운반/소유권 규칙 (들기, 이속 페널티, 이전 판정)
    BaseLock.ts       # 기지 잠금 상태 머신
    Rebirth.ts        # 환생 조건 체크와 보상
    Tools/            # 도구별 효과 모듈 (기절, 밀치기, 석화, 텔레포트...)
    Bots/             # 봇 AI (행동 트리: 방어/약탈/경제)
    events.ts         # 게임 내 이벤트 버스 (로직→렌더링 통신)
  render/             # Three.js 렌더링 계층
    Scene.ts          # 씬, 조명, 하늘
    MapBuilder.ts     # 레드카펫, 기지 8개, 지형
    CharacterMesh.ts  # 절차적 로우폴리 캐릭터 생성기 (파츠 조합)
    PlayerController.ts # 카메라+입력
    Effects.ts        # 파티클 (돈 틱, 변이 오라, 기절 별)
  ui/                 # HTML/CSS 오버레이 HUD
    HUD.ts            # 돈, 수입/s, 환생 게이지
    Shop.ts           # 도구 상점
    Inventory.ts      # 브레인롯 목록 (기지별)
    RebirthPanel.ts   # 환생 UI
  data/               # 정적 데이터 (JSON)
    brainrots.json    # 77종+ 스탯
    mutations.json    # 변이 배율
    tools.json        # 도구 정의
    rebirths.json     # 환생 요구치
  main.ts             # 부트스트랩 (core 생성 → render/ui 바인딩 → 루프)
```

**핵심 원칙**:
- `core/`는 DOM/Three.js 의존성 0 → 나중에 Node 서버에서 그대로 멀티플레이 시뮬레이션 가능
- core는 고정 타임스텝(20Hz)으로 시뮬레이션, 렌더링은 requestAnimationFrame 보간
- 모든 게임 데이터는 JSON (밸런스 조정 코드 불필요)

### 3.1 데이터 모델 (핵심)

```ts
interface Brainrot {
  id: string; name: string; rarity: Rarity;
  baseIncome: number;   // 초당 기본 수입
  price: number;        // 구매 가격
  mutation?: Mutation;  // 배율 적용
  ownerId: string | null;      // 기지 소유자
  slot: { baseId: number; floor: 1|2|3; index: number };
}
interface PlayerState {
  id: string; money: number; rebirth: number;
  baseId: number; unlockedFloors: 1|2|3;
  carrying: string | null;  // 브레인롯 id (들고 있으면 페널티)
  stunUntil: number; slowUntil: number;
  unlockedTools: string[]; activeTool: string;
}
```

### 3.2 봇 AI 설계

행동 트리 기반, 성격 3종:
- **약탈자(3명)**: 돈이 일정량 쌓이면 가장 가까운/가장 부유한 기지를 노리고 침입. 들면 도주 경로 선택
- **방어자(2명)**: 자기 기지 근처 순찰, 침입자 발견 시 방망이/메두사 대응, 잠금 적극 사용
- **경제형(2명)**: 스폰 브레인롯만 사서 수입 굴리기, 훔치기는 당할 때만 반격
난이도 파라미터: 반응 속도, 기지 잠금 사용 빈도, 도구 활용 수준

### 3.3 3D 비주얼

- 로우폴리 + 토이 룩 (밝은 색, 두꺼운 아웃라인은 후순위)
- 브레인롯 = 절차적 파츠 조합 (몸통 형태 × 재질 색 × 부속물(시계, 날개, 바퀴...)) — 등급별 실루엣 크기 증가
- 변이 = 머티리얼 색/쉐이더 (무지개 = HSL 순환 애니메이션, 갤럭시 = 스타 필드)
- 기지 = 컬러 테마별 모듈형 하우스, 층별 슬롯 진열대
- 돈 틱 = 브레인롯 머리 위로 $ 파티클 상승

## 5. 기술 스택

- **런타임**: TypeScript 5 + Vite
- **3D**: three.js (GLTF는 프로토타입에 한해, 본편은 코드 생성 메시)
- **UI**: HTML/CSS 오버레이 (React 불필요 — 게임 HUD는 바닐라로 충분)
- **테스트**: core 모듈에 Vitest 단위 테스트 (경제 계산, 소유권 규칙, 환생 조건)
- **빌드**: 정적 호스팅 (GitHub Pages 등 가능)
